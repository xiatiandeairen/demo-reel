# 问题模型

demo-reel 为什么做、做到什么算成、负责到哪。2026-11-21 初定，2026-11-24 按开源目标重新对齐；后续方案和用例以这里为准。

## 意图

项目发布时，让陌生人在 X、YouTube 或 GitHub 首屏 3 秒看懂"它做什么、为什么厉害"，觉得作者靠谱，然后 star、关注或试用。只服务这一个用途，不扩展到教程、版本更新说明。

起因：agent-quay 的演示 4 天里录了 3 次，每次改录制脚本都要逐帧重对镜头时间表。

## 用户和用法

- 用户：用 coding agent 的开发者，开源发布。
- 用法：只作为 agent 的 skill。用户一句话，agent 准备环境、和用户对齐后写剧本，再由 demo-reel 驱动录制、出片；用户只审成片。
- 独立：不依赖、不关联其他 skill。演示环境和设备由 agent 或用户准备好，demo-reel 不负责准备，也不负责借设备。
- 出片前对齐：写剧本之前，先和用户对齐语言（中文或英文，每次只出一种）、风格、主片讲哪一件事、场景表、每步字幕、结果卡数字的来源。

## 交付物

| 交付物 | 场景 | 内容 | 放哪 |
|---|---|---|---|
| `share.mp4`（1920×1080 H.264） | X、YouTube 共用 | 站外版，≤90 秒 | XDG data |
| `readme.mp4`（1280×720） | README 视频，经 GitHub 网页编辑器上传后引用附件地址 | README 版 | XDG data |
| `<名字>.gif` | README 首屏 | 主片，≤30 秒，只讲一件事，首尾可循环 | 被演示项目的 `assets/` |
| `share-presenter.mp4`、`readme-presenter.mp4` | 可选 | 对应制品加真人出镜 | XDG data |

站外版的默认框架：钩子（直接放结果）→ 问题 → 常见做法为什么不行 → 亮出名字 → 怎么用 → 证据 → 安装 → 行动号召和结尾卡。
README 版：去掉钩子、亮出名字和行动号召，其余同站外版。观众已经在仓库页上。
框架只是默认值，每个项目实际用哪几段，在出片前和用户对齐场景表。

X 和 YouTube 共用的前提：字幕烧进画面，关掉声音也看得懂；前 3 秒是钩子。
出现下面任一情况就拆开，X 改发主片导出的 1920×1080 mp4：发帖回看显示多数人看不到结果卡就划走了；X 视频时长上限核实后低于 90 秒。

## 目标

1. 一眼专业：背景、窗口框、字体、配色统一；首帧能看懂在演示什么；没有空等；不露私人信息。
2. 讲清一件事：主片、README 版、站外版各按上面的结构和时长。
3. 平台合规：每个交付物都在平台限制以内。
4. 稳定重录：剧本留在 `<项目>/.agents/demo-reel/<名字>/`；环境准备好以后，一条命令重录，不手调时间轴。
5. 交付前检查：录制前先做预检（环境是否就绪）和预演（不录屏先跑一遍演示）；出片后，机器检查 AI 看不到的四项：文件大小、格式和时长、敏感信息、配音响度；其余由 AI 看联系表审片。
6. 用现成工具驱动和拼装：终端用 VHS + tmux，iOS 和 Android 用 agent-device，网页用 agent-browser，Mac 用 agent-desktop 加系统录屏；合成只用 ffmpeg。

## 范围

- 录制对象（五端都是一等公民）：终端 CLI；iOS（模拟器、真机）；Android（模拟器、真机）；网页；Mac 窗口。
- 风格：克制的产品演示，真实操作录屏 + 镜头推拉 + 字幕。可选本地合成配音、真人出镜。
- 运行平台：只支持 macOS（iOS 和 Mac 录制只能在 macOS 上做）。

## 文件归属

规则：换一台电脑还用得上的进项目，用不上的放 XDG 目录。

| 位置 | 放什么 |
|---|---|
| `<项目>/.agents/demo-reel/<名字>/` | 一套制品的剧本、问题动画页面，以及 agent 写的准备、重置和替身脚本；准备脚本由 agent 执行，重置命令由 demo-reel 在预演和录制前调用；提交进 git。一个项目可以有多套 |
| `<项目>/assets/` | README 引用的 GIF |
| `$XDG_STATE_HOME/demo-reel/` | 录屏、事件、时间线、预演结果、指纹、卡片取值日志 |
| `$XDG_DATA_HOME/demo-reel/` | mp4 交付物、检查报告、联系表 |
| `$XDG_CACHE_HOME/demo-reel/` | 配音环境、模型、配音缓存 |
| `$XDG_CONFIG_HOME/demo-reel/` | `private.txt`：个人的私有检查规则，不进任何项目 |

进项目的文件会随项目公开：剧本和脚本里不写私有规则、凭证和内网地址。体积由项目自己负责。

## 职责边界

| 负责 | 不负责（为什么） |
|---|---|
| 和用户对齐剧本 | 准备演示环境：装被演示的工具、造数据、执行准备脚本、写重置命令，由 agent 做 |
| 录制前预检；调用 agent 提供的重置命令；预演 | 借设备：模拟器、真机、浏览器由 agent 或用户准备好 |
| 按剧本驱动演示并录屏 | 上传、发布到 X、YouTube、GitHub：对外动作 |
| 后期、导出；GIF 输出到 `<项目>/assets/<名字>.gif` | 清理旧的状态和产物目录：用户自己处理 |
| 机器检查和 AI 审片 | 帖子文案；为了好看改被演示项目的代码；功能短片；加工用户提供的素材；教程和版本更新说明 |

## 约束

- 真实性：被演示的工具真实运行；耗时太长的依赖可以用替身，并在剧本里注明；长等待剪掉。不伪造输出，片中数字来自录制日志。
- 平台上限：
  - GitHub：GIF、图片 10 MB；免费账号视频 10 MB。来源：[GitHub 文档](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/attaching-files)（2026-11-21 核对）。
  - X：GIF 15 MB。来源：[X 开发者文档](https://docs.x.com/x-api/media/quickstart/best-practices)。视频时长上限资料有冲突，未核实；90 秒以内的成品预计不受影响。
  - YouTube：MP4、H.264 High Profile、4:2:0。来源：[YouTube 推荐的上传编码设置](https://support.google.com/youtube/answer/1722171?hl=en)。1080p 码率搜到 8 Mbps 和 10 Mbps 两版，导出那一层核对。
- 录制环境：Mac 录制要屏幕录制权限；真机要用户解锁并打开调试或 UI 自动化。
