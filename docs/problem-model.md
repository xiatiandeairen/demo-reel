# 问题模型

demo-reel 为什么做、做到什么算成、负责到哪。2026-11-21 与用户分轮对齐后定稿；后续方案和用例以这里为准。

## 意图

发布一个项目或功能时，让陌生人在 X 时间线或 GitHub 首屏上 3 秒看懂"它做什么、为什么厉害"，觉得作者靠谱，然后 star、关注或试用。

起因：agent-quay 的演示 4 天里录了 3 次（提交 5937fb9、1b6c5e8、90dbb99），每次改录制脚本都要逐帧重对镜头时间表（`agent-quay/docs/demo/zoom.py` 的注释）。

## 目标

1. 一眼专业：窗口框、背景、字体、配色统一；首帧能看懂在演示什么；没有空等；不露私人信息。
2. 讲清一件事：每次一条主演示，30 秒以内，"问题 → 操作 → 结果"。
3. 多平台导出：同一条演示导出 X 用的 mp4 和 README 用的 GIF、mp4，都在平台限制内。HN 只能贴链接，由 README 首屏间接满足。
4. 能稳定重录：一句话重录，不手调时间轴；录制脚本留在被演示的项目里。
5. 交付前自动检查：尺寸、时长、文件大小、首帧、敏感信息过了检查才交付。
6. 用现成工具拼装：终端用 VHS，iOS 模拟器和真机用 agent-device，网页用 agent-browser，Mac 桌面用 agent-desktop 驱动加系统录屏；合成用 ffmpeg。2026-11-22 盲选 ffmpeg 与 Remotion 两版，用户看不出差别，按"更轻的技术栈"只留 ffmpeg。

## 范围

演示对象：终端 CLI、iOS App（模拟器或真机）、网页、Mac 桌面 App。风格：克制的产品演示（真实操作录屏 + 镜头推拉 + 少量标注 + 标题卡）。录制由 agent 全自动完成，用户只审成片。

## 职责边界

| 负责 | 不负责（为什么） |
|---|---|
| 写分镜、准备演示环境和数据、驱动录制、后期、导出、质检、留下可重录的脚本 | 写帖子文案：交给 x-post skill，避免两处各写一套 |
| | 上传或发布到 X、GitHub：对外动作，用户当次明确说了才做 |
| | 为了演示好看改被演示项目的代码：演示卡在缺陷上时只报告 |
| | 配乐、旁白：克制风格，且 X 默认静音自动播放 |
| | 中文版、每个功能单独的短片：这次只出一条英文主演示 |

交接：设备、浏览器的借用走 aq；帖子文案走 x-post。

## 约束

- 真实性：被演示的工具真实运行；耗时的依赖可以用替身并在脚本里注明；长等待剪掉。不伪造输出。
- 平台上限（2026-11-21 核对）：
  - GitHub：GIF、图片 10MB；免费账号仓库里的视频 10MB；推荐 H.264。来源：[GitHub 文档](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/attaching-files)。
  - X：GIF 15MB。来源：[X 开发者文档](https://docs.x.com/x-api/media/quickstart/best-practices)。普通账号视频时长多数资料写 140 秒，来源有冲突，未核实；30 秒主片不受影响。
  - 插件目录对 README 里的 GIF 是否有 5MB 限制：11-19 的会话计划里提过，`claude plugin validate` 未报，未核实。导出时 GIF 上限可按目标调。
- 录制环境：屏幕录制权限已授予（`agent-desktop permissions`）。
