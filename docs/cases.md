# 核心用例
仓库：https://github.com/xiatiandeairen/demo-reel · 本机：仓库根目录

每行守一个需求定义的行为。守它的测试在测试名或紧挨的注释里带编号（如 `# CASE-A1.1`），搜编号就能找到。

验证列：单元（纯逻辑，秒级，`python3 -m unittest`）、集成（真跑 ffmpeg、VHS、浏览器等，分钟级）、实录（真实录一条演示，加用户审片的标"审片"）。

## 环境

| 端 | 测试命令 | 依赖 |
|---|---|---|
| macOS | `bin/reel test`（单元）；`bin/reel test --integration`（集成） | python3 ≥ 3.11、ffmpeg、vhs、tmux、Homebrew bash ≥ 5（事件计时用 `$EPOCHREALTIME`）、Google Chrome（卡片渲染）、swift（OCR）；iOS 加 agent-device、网页加 agent-browser、Mac 加 agent-desktop |

## 外层验收

| 编号 | 场景 | 预期效果 | 验证 |
|---|---|---|---|
| CASE-A1 | 一句话给 aq 录演示 | 产出 X 用 mp4（1920×1080、H.264、≤30 秒）、README 用 GIF（≤10MB）和 mp4；统一背景、窗口框、标题卡、至少一处标注。不低于 aq 现有 `docs/demo/demo.gif`（2026-11-22 盲选：ffmpeg 与 Remotion 两版用户看不出差别，只留 ffmpeg） | 实录、审片 |
| CASE-A2 | 临时改一处 aq 的输出后一句话重录 | 不手改时间线；每个镜头都框住正在变化的窗格 | 实录 |
| CASE-A3 | 同样输入连录两次 | 镜头顺序相同；每次录制里镜头都在步骤开始前 0.3 秒内到位。两次之间的绝对时刻不比：真实执行快慢不同，实测差到 1.54 秒 | 实录 |
| CASE-A4 | 画面里有形如 token 的字符串、`/Users/<用户名>` 路径或内网域名；GIF 超上限；时长超 30 秒 | 不交付，报出第几秒并附截图；GIF 自动降帧率或尺寸，仍超就报错并列出各档大小；超时长报错 | 集成 |
| CASE-A5 | 演示中某一步失败（命令非零退出或期望文字没出现） | 停下，报告哪一步、输出是什么；不出成片；不改被演示项目 | 实录 |
| CASE-A6 | 一句话录 iPhone 真机上的 App（LiveTranslate 还没有界面，先用系统计算器） | 与 A1 同系列（背景、标题卡、设备外框），点击位置看得见，画面里没有个人信息 | 实录、审片 |
| CASE-A7 | 网页替身项目（TodoMVC） | 成片带鼠标光标，通过质检 | 实录 |
| CASE-A8 | Mac 替身（系统自带的文本编辑） | 成片通过质检，只录目标窗口，不录整个桌面 | 实录 |
| CASE-A9 | 新会话只读 SKILL.md，一句话给 agent-build（没有任何演示）从零出主演示 | 产出与 A1 同等的产物，分镜由 agent 自己写 | 实录（agent-verify） |
| CASE-A10 | demo-reel 仓库的中英 README | 首屏演示就是用 demo-reel 自己录的 | 实录 |

## 砍掉的用例

- 像素级成片快照比对：Chrome 或 ffmpeg 一升级就挂，外部行为没变。
- 单测动画曲线：审片能看出，内层重复。
- 真实上传到 X：对外动作，规格已由 A1.3 覆盖。
- 录制中途崩溃后的恢复：风险低，重跑即可。
