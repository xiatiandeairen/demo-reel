# 核心用例
仓库：https://github.com/xiatiandeairen/demo-reel · 本机：仓库根目录

每行守一个需求定义的行为。守它的测试在测试名或紧挨的注释里带编号（如 `# CASE-A1.1`），搜编号就能找到。

验证列：单元（纯逻辑，秒级，`python3 -m unittest`）、集成（真跑 ffmpeg、VHS、浏览器等，分钟级）、实录（真实录一条演示，加用户审片的标"审片"）。

## 环境

| 端 | 测试命令 | 依赖 |
|---|---|---|
| macOS | `python3 -m unittest discover -s tests`（单元）；前面加 `REEL_INTEGRATION=1`（集成，aq 的用例要先 `bin/reel make examples/aq/cli/reel.toml`） | python3 ≥ 3.11、ffmpeg、vhs、tmux、Homebrew bash ≥ 5（事件计时用 `$EPOCHREALTIME`）、Google Chrome（卡片渲染）、swift（OCR）；iOS、Android 加 agent-device，网页和动画加 agent-browser，Mac 加 agent-desktop |

## 砍掉的用例

- 口型逐帧对齐检测：审片能看出，自动测成本高。
- 几家配音引擎的自动 A/B：由用户试听决定。
- GIF 带声音：格式不支持。
- 功能短片（原 CASE-B6、B6.1）：2026-11-24 删除，不在交付物之内。
- `reel gc`（原 CASE-D6、D6.1）：2026-11-24 删除，清理旧目录不归 demo-reel。

- 像素级成片快照比对：Chrome 或 ffmpeg 一升级就挂，外部行为没变。
- 单测动画曲线：审片能看出，内层重复。
- 真实上传到 X：对外动作，规格已由 A1.3 覆盖。
- 录制中途崩溃后的恢复：风险低，重跑即可。
- 动画逐像素快照比对：一改配色就挂、外部行为却没变；审片代替。
- 场景转场、结果卡排版和字体的自动测试：联系表上一眼可见，自动化不划算。
- 场景失败时 aq 设备归还：沿用录制器原有的 finally 归还，没有新代码。
