# demo-reel

把和用户对齐过的剧本变成可以发布的成片。命令是本 skill 目录里的 `reel`（指向仓库的 `bin/reel`）。剧本字段的权威说明在 `reel/spec.py` 和各录制器文件开头（`reel/record_terminal.py`、`record_app.py`、`record_web.py`、`record_mac.py`、`record_animation.py`、`record_card.py`）；设计在 `docs/design.md`。

分工：你（agent）和用户对齐剧本、写剧本、准备演示环境和设备、审片、收尾；`reel` 负责预检、调用剧本里的 `reset`、预演、驱动演示并录屏、后期、导出、机器检查。上传和发布由用户决定。

## 出片前对齐

写剧本之前，先和用户逐项对齐下面 6 项，用户确认后才写。完成判据：6 项都有用户的明确答复。

1. 语言：中文或英文，每次只出一种（剧本的 `lang`）。
2. 风格：配色（`accent`，不写用默认）、要不要配音（`narrate`）、节奏快慢。
3. 主片讲哪一件事：README 首屏 GIF 用的那一段，"问题 → 操作 → 结果"，单独看得懂。
4. 场景表：站外版和 README 版各用哪几段（默认框架见下一节），每段演示什么。
5. 字幕：每一步一句，逐句给用户过目。
6. 数字：结果卡上有哪些数字、各从哪份录制日志算出来；没有能量化的数字就不放结果卡。

## 成片标准

审片和交付按这一节判断，写剧本时也照它定节奏和镜头。机器检查只管 AI 看不到的（大小、格式和时长、敏感信息、响度、交付物是否最新），其余由你看联系表判断。

**三种制品**

| 制品 | 场景 | 内容 | 位置 |
|---|---|---|---|
| `share.mp4`（1920×1080 H.264 High） | X、YouTube 共用 | 站外版，≤90 秒 | XDG data 目录 |
| `readme.mp4`（1280×720，≤10 MB） | README 视频 | README 版，≤90 秒 | XDG data 目录；要经 GitHub 网页编辑器上传后引用附件地址才能播放 |
| `<名字>.gif`（≤10 MB） | README 首屏 | 主片，≤30 秒，首尾能循环 | `<项目>/assets/<名字>.gif` |

三种制品每次都出：用户只要 GIF 时，`[share]` 和 `[readme]` 也照写，只列主片那一段。

站外版的默认框架：钩子（直接放结果卡）→ 问题动画 → 常见做法为什么不行 → 亮出名字 → 怎么用（加 1～2 个关键功能）→ 结果卡 → 安装 → 行动号召和结尾卡。README 版去掉钩子、亮出名字和行动号召。框架只是默认，以对齐的场景表为准。

**共同标准**
- 第一眼：第一帧就是内容（站外版是钩子），没有标题卡；前 3 秒关掉声音也看得懂。
- 静音可懂：每段都有字幕，最多两行；没写 `say` 的步骤沿用上一句；字幕不遮挡标签和关键画面。
- 节奏：没有空等（超过 1.2 秒的静止被剪），等待中间用 `squeeze` 剪；场景之间淡入淡出。
- 镜头：终端推近到正在变化的几行，读得清；手机、网页、Mac 窗口完整显示。
- 真实：被演示的工具真实运行，输出不伪造；耗时太长的依赖用替身脚本并在剧本里注明；片中数字来自录制日志。
- 隐私：画面里没有家目录路径、用户名、token、私有规则（`~/.config/demo-reel/private.txt`）；真机录制时状态栏、通知、账号名会原样录进去。
- 声音：开了配音时每句都说完才进下一步，整片 -16 LUFS。
- 性能对比：比较快慢的命令写 `timer`，按真实时长播放不剪，所有计时条共用一个比例尺；结果卡用条形图，数字和计时条一致。

## 写剧本

一个项目可以有多套制品，每套一个目录，提交进被演示项目的 git：

```
<项目>/.agents/demo-reel/<名字>/
  reel.toml          总剧本：lang、narrate、accent，[share] [readme] 的场景顺序，[gif] 主片，[card.<id>] 卡片
  scenes/<id>.toml   要录制或渲染的场景，kind 为 terminal、ios、android、web、mac、animation
  scenes/<id>.html   问题动画页面
  scripts/           你写的准备、重置、收尾和替身脚本
```

已经存在时在原文件上改，它是以后重录的依据。写法照 `examples/` 里的几套（`examples/aq/cli` 最完整，`examples/hello/cli` 最小）。剧本会随项目公开：不写凭证、内网地址和私有规则；设备号写成环境变量。用了已删除的字段，`reel` 会报出哪个文件、哪个字段、改用什么。

**每一步**
- `say`：一句完整的短句，不复述命令；开配音时英文每句 3～6 个词、中文 15 字以内；第一步必须写。
- `wait`：每个要等的结果都写；等不到就判失败，不会带着跑坏的画面出片。终端的 `wait` 是整屏文字上的正则，屏幕上已有的旧输出也算：等第二次出现写成 `ok[\s\S]*ok`。超时由预演实测耗时自动算出。
- `hold`：通常不写，默认按配音或阅读时长；只在没有字幕、要快速连按的步骤上写。
- 动词：终端用 `type`；App、网页、Mac 用 `click`、`fill`、`type`、`key`、`scroll`、`back`（Mac 只有 `click`、`type`、`key`；手机的 `key` 只能按回车）。选择器写法跟着各端工具走，先用 `agent-device snapshot -i`、`agent-browser snapshot` 看名字。

**终端**
- 在中性工作目录里演示（`workdir`，看不到家目录）；镜头默认推近到正在打字的窗格，整屏写 `focus = "full"`，一直刷新的看板用 `[[pane]] run`。
- 关键数字单独打印一行（如 `build 5.1s → 1.5s`）；长路径先放进准备脚本或别名。
- 结果卡要用的日志写 `keep_files`，卡片里写 `{files:<场景 id>}/runs.log`。
- 旁白里的数量词以实测为准：先手动跑一遍看耗时和输出行数。

**设备**
- 场景只需要一台设备、不演示借设备的过程：准备或重置脚本用 `simctl`（或 Android 的 `emulator`）建一台固定名字的模拟器，不要从 aq 这类设备池借（参照 `examples/aq/cli/scripts/sim-boot.sh`）；池里借的设备场景结束后不会自动归还，后面的场景会借不到。
- 演示内容本身就是借设备：在这个场景的 `reset` 开头先归还上一次借的，再重新准备。
- 终端旁边并排的模拟器写 `[[device]] name` 和 `find`（打印设备号的命令，设备可以在演示中途才出现）。

**卡片和动画**
- 卡片写在 `reel.toml` 的 `[card.<id>]`：`lines` 加 `values`（每个值是一条命令的输出），或 `bars`（条形图，值可以引用某个场景的计时条）。命令失败或没输出就停止出片。
- 问题动画是 1920×1080 的 HTML 页面加 CSS 动画，每个 `animation` 都写 `both`；时长按最后一个动画结束自动算。

## 准备环境（你来做）

`reel make` 之前：
- 装好被演示的工具；要录当前检出的构建，在准备脚本里先编译、把产物目录放到 PATH 前面。
- 每个场景的初始状态由它的 `reset` 命令保证：`reel` 在预演和录制之前各调用一次（在剧本目录里执行，终端场景带 `REEL_WORK`）。会改用户配置的演示（如安装插件）指到临时配置目录，`reset` 从空目录开始。
- iOS 和 Android：启动模拟器或连好真机，把设备号放进剧本写的环境变量。真机要用户解锁、关掉自动锁定、打开调试或 UI 自动化，这些请用户做；签名变量放在环境里。
- 网页：先把页面服务起来（`preflight` 会检查能否访问）。
- Mac：把要录的窗口打开放在前面，屏幕亮着，有录屏权限。

## 出片

按顺序做，每步达到完成判据再往下。

1. 对齐并写剧本（见上两节）。完成判据：用户确认过 6 项；剧本和脚本都在 `<项目>/.agents/demo-reel/<名字>/` 下。
2. 准备环境（见上一节）。
3. 运行 `reel make <项目>/.agents/demo-reel/<名字>/reel.toml`。它先预检，缺什么就列出来停下；每个场景先预演再录制；只重做输入变了的部分。被演示的工具升级了、或环境变了而剧本没变，加 `--rerecord`。完成判据：结尾打印 `PASS`，CHECKS 每项 `ok`；`FAIL` 时按它给的原因和建议修，再运行。
4. 审片：打开结尾列出的三张联系表（`sheet-share.png`、`sheet-readme.png`、`sheet-gif.png`，各 24 格），逐格对照"成片标准"。完成判据：每一处问题都记下第几格、什么问题；有问题就改剧本或环境再 `reel make`（只改字幕和镜头不会重录）。
5. 真人出镜（用户要时）：请用户在自己的终端运行 `reel narrate <剧本> --cut share`（README 版用 `--cut readme`），边看边讲。完成判据：产物目录里有 `share-presenter.mp4` 或 `readme-presenter.mp4`。
6. 交付和收尾。完成判据：用户拿到每个文件的路径、时长、大小、检查结果和审片记下的问题；GIF 已在 `<项目>/assets/<名字>.gif`，README 里用 `![<一句话说明>](assets/<名字>.gif)` 引用；你借的设备已归还、起的服务已停（演示的 teardown 脚本）；提交、推送、上传等用户说了再做。

## 出错时

| 现象 | 怎么办 |
|---|---|
| `FAIL script` | 剧本字段写错或用了已删除的字段：按提示改 |
| `FAIL preflight` | 按列出的项准备环境（工具、工作目录、设备、页面服务） |
| `FAIL reset` | 你写的重置命令出错：单独运行它看输出 |
| `FAIL rehearse` / `FAIL record` | 演示本身出错：如实告诉用户哪一步、什么输出；被演示项目的代码保持原样 |
| `sensitive` 为 FAIL | 看 `leaks/` 截图，改剧本或环境让它不出现，再 `reel make --rerecord`；检查规则保持原样 |
| `size` 为 FAIL | 缩短主片或减少整屏变化 |
| `export` 报 assets 里的同名文件不是 demo-reel 写的 | 请用户处理那个文件，或换个名字 |
| 镜头切得早或晚、框错了 | 检查 `focus`；开发者可用 `reel/planner.py` 的 `sync_report` 对比时间 |

## 依赖

macOS、python3 ≥ 3.11、ffmpeg、Google Chrome；终端加 vhs、tmux、Homebrew bash；iOS 加 agent-device 和 Xcode；Android 加 agent-device 和 Android SDK（adb、emulator）；网页和动画加 agent-browser；Mac 加 agent-desktop。配音和真人出镜另需 uv（第一次用会在 `~/.cache/demo-reel/` 装环境、下模型，要十几分钟），出镜还要 ffplay 和摄像头。
