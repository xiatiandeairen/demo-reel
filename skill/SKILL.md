# demo-reel

把分镜文件变成可以直接发布的成片。命令是本 skill 目录里的 `reel`（指向仓库的 `bin/reel`），下文写作 `reel`；分镜字段的权威说明在各录制器文件开头（`reel/record_terminal.py`、`record_ios.py`、`record_web.py`、`record_mac.py`、`record_animation.py`、`record_card.py`）和 `reel/spec.py`。

## 成片标准

审片和交付都按这一节判断。每条是"情形：效果"。

**第一眼**
- 任何成片：第一帧就是产品画面，陌生人不读字也知道在演示什么；标题和链接放在帖子文字里，标题卡只在分镜写了 `intro = true` 时出现。
- 完整介绍片：前几秒用一段动画讲清"遇到什么问题"，不懂终端的人也看得懂。

**节奏**
- 观看时：没有空等；超过 1.2 秒的静止画面被剪到两侧各留 0.35 秒，标了 `squeeze` 的等待（页面加载、克隆仓库）连在动的画面也剪。
- 开场和结尾：先在全景停 1.5 秒再推进去，结尾拉回全景停 1.8 秒后淡出；功能短片首尾相接、循环播放不跳。
- 时长：主片 30 秒以内、讲一件事；功能短片 4～15 秒；分场景介绍片 90 秒以内，场景之间淡入淡出。

**镜头**
- 终端：推到正在变化的那几行，最多 2.5 倍，左边对齐窗格，读得清命令和输出；别处同时变化时镜头跟过去。
- 网页：画面里有放大、平滑移动的光标，点击处有涟漪。
- Mac 窗口和 iPhone：始终完整显示窗口或整台手机。
- 终端旁边并排的模拟器：手机在命令之后才变，成片里 3 秒以内出现结果。

**字幕和声音**
- 静音观看：每步底部一句英文字幕，说发生了什么、为什么值得看，最多两行；靠按键完成的步骤，句末显示按键徽标。
- 开声音：可选本地合成配音（am_michael 美式男声、bf_emma 英式女声），每句都说完才进下一步，整片响度 -16 LUFS；可选真人出镜，右下角摄像头小窗以脸为中心，字幕来自本人说的话。

**性能对比**
- 比较两次运行的快慢：两次都在同样条件下真实运行、按真实时长播放不剪；底部的计时进度条用同一个比例尺，慢的那条走得久、停得远，观众不看数字也比得出来；结果卡用条形图，数字和计时进度条一致。

**真实可信**
- 被演示的工具真实运行，输出不伪造；耗时太长的依赖用替身脚本，分镜开头注释写明谁是替身。
- 每个要等的结果都写了 `wait`：等不到就判录制失败，不会带着跑坏的画面出片。
- 片子里出现的数字来自录制日志（结果卡的取值命令），不手写。

**隐私**
- 画面里没有家目录路径、用户名、token、API key 和 `~/.config/demo-reel/private.txt` 里的私有规则；检查每半秒做一次文字识别，命中就不交付并附截图。
- 真机录制：状态栏、通知、账号名会原样录进去，选不含个人信息的 App 和页面。

**交付物**（在 `$XDG_DATA_HOME/demo-reel/<片名>-<短哈希>/`，默认 `~/.local/share/...`）
- `x.mp4`：X 时间线用，1920×1080 H.264。
- `readme.mp4` 和 `readme.gif`：GitHub README 用，都不超过 10 MB；GIF 超限时自动降尺寸和帧率，仍超就报错并列出各档大小。
- `clips/<名字>.mp4` 和 `.gif`：功能短片；`x-presenter.mp4`：真人出镜版。
- 被演示的项目里只放最终用的那份 GIF 或视频，分镜和脚本留在 demo-reel 仓库。

**可重录**
- 改了被演示的工具：一条 `reel make` 重录，不手调时间线。
- 介绍片里只有一个场景要改：`reel make <场景>.toml` 只重录这一段，`reel compose film.toml` 重新拼接，其他场景不动。
- 只改了手机的排布或对齐：`reel plan` 加 `reel compose`，原始录像不动。

## 写分镜

分镜写在 demo-reel 仓库的 `examples/<项目名>/`（仓库根目录是 `reel` 软链所指文件的上两级），准备脚本和替身脚本放在旁边；写法照 `examples/` 里现有的几个。每条是"情形：效果"。

**讲法**
- 主片：一条只讲一件事，"问题 → 操作 → 结果"，3～8 步；想法不止一个时，用 `[film] from/to` 只把前几步放进主片，其余步骤用 `[[clip]]` 出短片，都来自同一次录制。
- 旁白 `say`：一句完整的英文短句，不复述命令；开配音时每句 3～6 个词，8 步合计 15 秒左右。产品名读不准时加 `speak` 写拼读，字幕仍显示 `say`。
- 结论：关键数字单独打印一行（如 `build 5.1s → 1.5s`），观众一眼看得到。

**分场景介绍片**（`film.toml`，参照 `examples/aq/film.toml`）
- 结构："问题动画 → 没有这个工具 → 有这个工具 → 关键功能 → 结果卡 → 安装"，每个场景一份普通分镜，各自写 `[voice]`，单独重录时声音才一致。
- 问题动画（`kind = "animation"`）：一个 HTML 页面加 CSS 动画，逐帧渲染、不推镜头不剪；每个 `animation` 都写 `both`，开始前和结束后才停在首尾帧。
- 结果卡（`kind = "card"`）：每个数字是一条 shell 命令从录制日志算出来的，命令失败或没输出就停止出片，每次拼接都重画。
- 排在后面的终端场景：写 `[terminal] open_hold = 0.6`，开场不再停 1.5 秒。
- 安装场景：照实运行 README 里的安装命令；本机已装时输出就是"already installed"，照实录。会改用户配置的安装（如 Claude Code 插件）指到临时配置目录，场景收尾比对用户自己的配置没变（参照 `examples/aq/install.toml`）。

**GIF 和介绍片的分工**
- 只要 README 首屏一张会动的图：一个 `reel.toml` 就够，同一次录制同时出 GIF 和 mp4。
- 首屏要短 GIF、另有完整介绍片：GIF 用 `reel.toml` 讲用法和效果；介绍片用 `film.toml`，可以把 `reel.toml` 直接列成其中一个场景，共用同一段录制。GIF 有 10 MB 上限，长片的 GIF 会被压到很糊，长内容只出 mp4。

**性能对比**（参照 `examples/agent-build/`）
- 要比较的命令所在的步骤写 `timer = "<名字>"`：这条命令运行期间不剪，底部画一条计时进度条，结束时显示秒数；所有场景写同一个顶层 `timer_scale`（整条代表多少秒），不同场景的进度条才能直接比。只要不剪、不要进度条时写 `keep_time = true`。
- 对比的两边条件相同：同一个项目、同样的前置状态（在准备脚本里做），只差被演示的工具；同一个场景里放两条计时，两条会上下并排。
- 结果卡写 `[[card.bars]]`：每组几根横条，长度按数值成比例；数值可以引用某个场景的计时（`{ scene = "<场景>.toml", timer = "<名字>" }`），和进度条上的秒数一致。
- 旁白里的数量词以实测为准：先手动跑一遍看耗时和输出行数，再写"hundreds of lines"这类话。

**终端**
- 画面：在 `/tmp` 下的中性目录跑（`workdir`，每次录制前清空），看不到家目录；单窗格字号 48～54，README 宽度下也读得清；一直刷新的看板窗格标 `noisy = true`。
- 打字：每字 45 毫秒，80 个字符约 3.6 秒，长路径先放进准备脚本或别名。
- 有意失败的命令：那一步写 `allow_fail = true`；其他命令非零退出就判录制失败。
- `wait` 是整屏文字上的正则，屏幕上已有的旧输出也算：等第二次出现写成 `ok[\s\S]*ok`。
- 开了配音：每步都停到这句话说完，靠时机才出现的画面（如"排队中"）可能已经过去，`wait` 会失败；这时把替身脚本的耗时加长，`wait` 留着。

**终端旁边并排模拟器**（`[[device]]`，参照 `examples/aq/borrow.toml` 和 `setup-sims.sh`）
- 手机在画面上：每台写 `name`（手机下方的标签）和 `find`（打印出模拟器 UDID 时开始录这台手机，之前显示暗色空手机）。
- 手机上的结果：演示命令等到画面里真的出现结果才返回并打印一行，步骤用 `wait` 等这一行，并加 `squeeze = true`。录屏时页面加载要 2～5 秒，Safari 首次启动要 10～15 秒，这样等待才会被剪掉。
- 页面服务用系统的 `/usr/bin/python3`；pyenv 的 python3 垫片在后台启动会卡住。

**iOS 真机和网页**
- 真机：`[ios] device = "physical"`，经 aq 借用户登记过的 iPhone；签名变量放在环境里（项目或工作区说明里有就照用），不写进分镜。手机要解锁、自动锁定设为永不、打开 Enable UI Automation，这些请用户做。按钮名跟着手机语言走，先用 `agent-device open <app>` 看快照里的名字；即时响应的 App 加 `settle = false`，每步少等 3 秒左右。
- 等待：网页和 iOS 的 `wait` 是选择器，如 `text="Done"`、`value="36"`。

## 出片

按顺序做，每步达到完成判据再往下。

1. 写分镜（见上一节）：先读被演示项目的 README 和 `--help`，挑出最能说明它价值的一个"问题 → 操作 → 结果"；`examples/<项目名>/` 已经存在时在原文件上改，它是以后重录的依据。完成判据：分镜和脚本都在 `examples/<项目名>/` 下，被演示的项目里没有新增文件。
2. 运行 `reel make examples/<项目名>/<分镜>.toml`（介绍片用 `film.toml`）。录的是 PATH 上的工具；要录当前检出的构建，在准备脚本里先编译、把产物目录放到 PATH 前面。完成判据：结尾打印 `check: PASS`，每项都是 `ok`；有 `BAD` 按下方"出错时"修到全部 ok。
3. 运行 `reel sheet <同一份分镜>`，打开产物目录里的 `sheet.png`（24 格，覆盖全片）。完成判据：逐格对照"成片标准"看过；首帧、每个镜头框住的位置、字幕和画面是否对得上、有没有截断，每一处问题都记下秒数。
4. 真人出镜（用户要时）：请用户在自己的终端运行 `reel narrate <分镜>`，边看成片边讲；第一次会要摄像头和麦克风权限。脸贴着摄像头画面底边时没法居中，请用户坐正；底噪明显时请用户离麦克风近一些再录。完成判据：产物目录里有 `x-presenter.mp4` 和 `readme-presenter.mp4`。
5. 交付。完成判据：用户拿到每个文件的路径、时长、大小、检查结果和审片记下的问题；要放进项目的那份已复制到项目里（如 `docs/demo/demo.gif`），README 里用 `![<一句话说明>](docs/demo/demo.gif)` 引用；提交和推送等用户说了再做。
6. 带声音的视频放进 GitHub README（用户要时；GIF 没有声音）：用户说了"帮我放上去"就是同意，只问"怎么弄"时先讲步骤、再问要不要代办。用用户已登录的浏览器打开 GitHub 网页文件编辑器，上传视频，编辑器会在光标处插入一个 `https://github.com/user-attachments/assets/...` 地址，让它单独占一行（GitHub 才会渲染成播放器），并在网页上提交那次编辑。只上传不提交、或用 git 推送引用同一地址，地址对上传者以外的人一律 404（2026-11-22 在 agent-quay 实测）。完成判据：用没有登录 GitHub 的浏览器（如 Claude 内置浏览器）打开 README，视频能播放。帖子文案交给 x-post。

## 出错时

| 现象 | 怎么办 |
|---|---|
| `step N failed` / `exited with` | 演示本身出错了：如实告诉用户哪一步、什么输出；被演示项目的代码保持原样 |
| `sensitive text` 为 BAD | 看产物目录里的 `leaks/` 截图，改分镜或准备脚本让它不出现，再重录；检查规则保持原样 |
| `readme.gif size` 为 BAD | 缩短演示或减少整屏变化；`gif_max_mb` 只能调低，上限 10 |
| `no active display`（Mac） | 屏幕没亮或已锁定，请用户在场时再录 |
| `clips/... loops` 为 BAD | 短片范围的最后一步还在大幅变化：把 `to` 改到画面稳定的那一步 |
| `narration loudness` 为 BAD | 配音没混进去：看状态目录的 `voice/` 里有没有每步的 wav |
| `scene <名字>: ...`（介绍片） | 那个场景失败了，其他场景的录制还在：修好后 `reel make <场景>.toml`，再 `reel compose film.toml` |
| `no recording of <设备>` | `[[device]]` 的 `find` 一直没打印出 UDID：确认准备脚本借到了模拟器、`find` 命令能单独跑通 |
| 镜头切得早或晚 | 看 `reel sync <目录>` 的 delta |

## 依赖

python3 ≥ 3.11、ffmpeg、Google Chrome；终端加 vhs、tmux、Homebrew bash；iOS 加 agent-device；网页和动画加 agent-browser；模拟器和浏览器都经 aq 借用。配音和真人出镜另需 uv（第一次用会在 `~/.cache/demo-reel/` 装环境、下模型，要十几分钟），出镜还要 ffplay 和摄像头。
